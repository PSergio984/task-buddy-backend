# Avatar/icon library options — research findings

**Ticket:** [Avatar/icon library options (#51)](https://github.com/PSergio984/task-buddy-backend/issues/51)
**Context:** Task Buddy (FastAPI + Next.js web + React Native mobile) is adding a gamified focus layer. Users get a customizable in-app avatar; a mascot (doubling as the app icon) comes later. Gear/equipment overlay is a requirement under the gamification model.
**Date:** 2026-11-01

## TL;DR

- **DiceBear** is the strongest default: MIT-licensed engine, 61 styles, per-style slot options (`hairVariant`, `glassesVariant`, …), official React Native + Next.js guides, HTTP API that can emit PNG for `next/image`/RN `Image`, and a documented JSON component model that can host a custom gear layer.
- **License caveat inside DiceBear:** style licenses differ. `pixel-art`/`open-peeps`/`notionists`/`lorelei` are CC0; **`adventurer` is CC BY 4.0** (attribution required); `avataaars`/`bottts` use the artist's own "free for personal and commercial use" terms.
- **Avoid as primary:** Multi Avatar (custom license bars re-branding/competing avatar services; repo unmaintained since 2022-03) and the original `avataaars` React component (stale: npm last publish 2021-08, avataaars.com TLS cert expired).
- Boring Avatars, Open Peeps, and minidenticons are flat/seed-only generators — fine for *default* avatars, wrong shape for gear overlay.
- Gear overlay is best served by a layered/slot model (DiceBear components, Avataaars-style props) plus a hand-rolled SVG overlay layer for equipped items.

## 1. Candidate libraries — license, style, customization, maintenance

**DiceBear** — Open-source avatar engine + collection. Code MIT; each of the 61 styles carries its creator's license: 42 CC0 styles (incl. `pixel-art`/`pixel-art-neutral`, `open-peeps`, `notionists`/`notionists-neutral`, `lorelei`, `pixelbot`, `critters`, `voxel-bot`), 14 CC BY 4.0 remixes (incl. **`adventurer`/`adventurer-neutral`**, `big-ears`, `big-smile`, `micah`, `personas`, `croodles`, `miniavs`), `icons` MIT (Bootstrap Icons), and `avataaars`/`bottts` (+ `-neutral` variants) under Pablo Stanley's "free for personal and commercial use" terms ([licenses page](https://www.dicebear.com/licenses/)). Customization: two layers — core options identical across styles (`seed`, `flip`, `rotate`, `scale`, `borderRadius`, `size`, `backgroundColor`, `tags`, …) and per-style enumerated component options exposed as `<component>Variant` + `<component>Probability` + color options; the HTTP API publishes each style's options as machine-readable `options.json` ([HTTP API docs](https://www.dicebear.com/integrations/http-api/)). Concrete: `adventurer` offers hair=45 variants, mouth=30, eyes=26, eyebrows=15, earrings=6, glasses=5 plus ~10 color groups (measured via `https://api.dicebear.com/10.x/adventurer/options.json` + `definition.json`, 2026-11-01). Maintenance: very active — `dicebear/dicebear` pushed 2026-10-29, ~10k stars, `@dicebear/core` 10.7.0 published 2026-08-26; ports exist for PHP/Python/Rust/Go/Dart/C# and a CLI ([docs nav](https://www.dicebear.com/)).

**Boring Avatars** — MIT React library generating flat geometric avatars from any string; six variants (`marble`, `beam`, `pixel`, `sunset`, `ring`, `bauhaus`) ([README](https://github.com/boringdesigners/boring-avatars)). Customization stops at `name`/`variant`/`colors`/`size`/`square` — deterministic seed-in, picture-out; no trait pickers, so it can't power a *customizable* avatar editor (only nice defaults). Repo still receives commits (2026-06-19); npm 2.0.4 (2025-09-28). Authors also sell a hosted API subscription — the library itself is free MIT.

**Avataaars (original React component)** — MIT component wrapping Pablo Stanley's CC-like "free for personal and commercial use" Sketch artwork. Trait props map 1:1 to gear-style slots (`topType`, `accessoriesType`, `clotheType`, `facialHairType`, `eyeType`, `mouthType`, `skinColor`) and a `Piece` component can render any single slot ([README](https://github.com/fangpenlin/avataaars)). But the package is stale: `avataaars@2.0.0` published 2021-08-15, repo last pushed 2024-03-04, 33 open issues, and `avataaars.com` currently serves an expired TLS certificate. The maintained path to the same art is DiceBear's `avataaars`/`avataaars-neutral` styles ([licenses](https://www.dicebear.com/licenses/)).

**Open Peeps** — Pablo Stanley's hand-drawn, mix-and-match illustration library, CC0 ("Free for commercial and personal use") ([openpeeps.com](https://www.openpeeps.com/)). It's an asset pack (PNG/SVG/Figma/Sketch/Blush), not a runtime generator — building a trait picker means shipping the parts and compositing them yourself. DiceBear's `open-peeps` style (CC0) already packages the same art as a generator.

**Multi Avatar** — Single-file vanilla-JS generator (SHA-256 → SVG; 68 KB min) plus hosted API (`api.multiavatar.com/<id>.svg|.png`) ([README](https://github.com/multiavatar/Multiavatar)). Internally composites 6 parts + 3 color themes, but trait choice is hash-driven — users get a seed, not a picker. License is custom: free incl. commercial, **but** it forbids re-packaging/re-branding the asset set and building a "similar or competing product/service," and the avatar must remain "an addition to your product, but not the product on its own" ([LICENSE](https://raw.githubusercontent.com/multiavatar/Multiavatar/main/LICENSE)). Repo unmaintained since 2022-03-26. Usable in-app, but the bespoke license + dormancy argues against it.

**Notion-style builders** — `Mayandev/notion-avatar`: MIT Next.js editor, assets CC0 ("Noto avatar" pack), actively developed with recent AI features ([repo](https://github.com/Mayandev/notion-avatar)). Users pick parts in an editor and export a flat image — good look, no runtime slot API of its own. Equivalent generator styles exist inside DiceBear (`notionists`, `notionists-neutral`, CC0, remixing Zoish's Notionists pack) ([licenses](https://www.dicebear.com/licenses/)).

**Nice Avatar** — `react-nice-avatar` (MIT): React component with `genConfig(seed)` or explicit trait props (face, hair, hat, shirt, accessories, colors) ([README](https://github.com/dapi-labs/react-nice-avatar)). Slot-prop model like Avataaars. npm 1.5.0 (2023-11-28); repo moved to `dapi-labs/react-nice-avatar`.

**Minidenticons** — MIT, ~300-byte identicon generator (SVG, username-hash → pixelated pattern) ([repo](https://github.com/laurentpayot/minidenticons)). Traitless; only useful as cheap default avatars.

**Pixel-art kits** — DiceBear `pixel-art` (CC0, DiceBear-authored) covers the "retro sprite" need inside a supported engine: options `accessories`, `beard`, `clothes`, `eyes`, `glasses`, `hair`, `hat`, `mouth` variants + per-group colors (via `options.json`); `pixelbot`/`voxel-bot`/`voxel-art` are adjacent CC0 pixel styles ([style page](https://www.dicebear.com/styles/pixel-art/)). Generic itch.io sprite-sheet kits can be more characterful but each needs a license audit and bespoke compositing code.

## 2. Layering / composition model — can equipped GEAR overlay the avatar?

- **DiceBear — yes, two ways.** (a) Styles are JSON definitions: `canvas.elements` is an *ordered* layer stack where entries of `"type": "component"` reference a slot whose `variants` (with `probability`) the PRNG picks ([create-a-style guide](https://www.dicebear.com/create-styles/from-scratch/)). A forked/derived style can add `armor`, `pet`, `aura` components — or a `gear` component can be appended to render above the face. (b) Without touching the style, compose two SVGs: render avatar, then absolutely position a gear SVG layer (web: CSS stacking; RN: stacked `SvgXml`/`Image`). DiceBear's `OptionContext`-free `Style`/`Avatar` API and per-component `definition.json` make either route deterministic.
- **Avataaars-style slot props (`avataaars`, `react-nice-avatar`)** — the model already is "one component per slot" (`top`, `accessories`, `clothe`…), so gear slots fit naturally, but adding a *new* slot means editing component source — there's no runtime plugin system.
- **Boring Avatars / Multi Avatar / minidenticons** — flat single-SVG output; gear only via an external overlay layer (feasible but you'd own alignment/scaling per variant — brittle for multi-variant styles).
- **Open Peeps / sprite kits** — the source art *is* layers; you composite part PNGs/SVGs in fixed z-order, so gear layers are trivial *if* you build the compositor yourself.
- Practical note: any gear system benefits from a **bounded, curated style** (one art family, fixed canvas anchors) rather than an open generator — e.g., lock Task Buddy avatars to 1–2 DiceBear styles so gear hitboxes are known.

## 3. Rendering support — React (web/Next.js) AND React Native

- **DiceBear — official support for both.** RN: `@dicebear/core` produces an SVG string rendered via `react-native-svg`'s `SvgXml`, or the HTTP API's `/png` endpoint feeds RN's built-in `Image` with zero extra deps ([RN guide](https://www.dicebear.com/integrations/javascript/react-native/)). Next.js: documented patterns for App-Router server components (`.toDataUri()` → `<img>`), client components (`useMemo`), route handlers, Pages Router, and `next/image` against the HTTP API using raster formats (PNG/WebP/AVIF — `next/image` won't optimize SVG) ([Next.js guide](https://www.dicebear.com/integrations/javascript/next-js/)). `react-native-svg` itself is MIT and actively maintained (8k stars, pushed 2026-10-29) ([repo](https://github.com/software-mansion/react-native-svg)).
- **Boring Avatars — web-only officially.** It's a JSX/SVG React component; RN needs a `react-native-svg` port — community `react-native-boring-avatars` is v1.0.1 (2021-07, unmaintained). Porting is mechanical (few elements) but unowned.
- **Avataaars component — web-only officially.** `react-native-avataaars` exists at v1.0.2 (2019, stale). DiceBear `avataaars` removes this gap.
- **Multi Avatar — platform-agnostic.** The JS lib returns an SVG string (`react-native-svg`) and the hosted API serves `.png` (`Image`) — but see license/dormancy flags.
- **Open Peeps / Notion-avatar / pixel kits — asset-based.** PNG/SVG files render identically on both platforms; no framework dependency.
- **Nice Avatar — web React component.** RN usage unverified (no official binding found).

## 4. Mascot relationship — how does each option feed a later mascot/app icon?

- **DiceBear:** purpose-fit mascot styles exist — `bottts`/`bottts-neutral` (robots; artist-terms license), `pixelbot`, `critters`, `voxel-bot`, `fun-emoji`, `thumbs` — so the mascot can be generated in the same pipeline and visually "family" with user avatars. `next/image`-friendly PNG/WebP output covers app-icon raster sizes via HTTP API or `@dicebear/converter` ([HTTP API](https://www.dicebear.com/integrations/http-api/), [licenses](https://www.dicebear.com/licenses/)). Caveat: a *generated* mascot is shared-namespace art — any other app can generate the identical robot. For a unique brand mark, treat the generator as mood-board/prototype and commission final art in a compatible line style (Adventurer/Lorelei's bold-outline look is a common commission style).
- **Open Peeps / Notion-style:** wrong register — people illustrations, weak mascot candidates; mascot would be separately commissioned.
- **Boring Avatars / minidenticons:** abstract marks could *inspire* a logo (bauhaus/pixel motifs echo app-icon minimalism) but can't depict a character mascot.
- **Avataaars/Nice Avatar/Multi Avatar:** human/face-centric; Multi Avatar's license additionally blocks re-branding the asset set as your own mark — disqualifying for "mascot as app icon." Commissioned art is independent of whichever generator is picked for avatars.

## 5. Storage implications — config-blob vs rendered assets

- **Config-blob-per-user (seed + trait selections):** the natural model for deterministic generators — **DiceBear** (store `seed` + options JSON; identical SVG re-derived anywhere, even server-side or via `api.dicebear.com` URL with the same query params — documented "same seed always returns the same image" [HTTP API](https://www.dicebear.com/integrations/http-api/)), **Boring Avatars** (`name`+`variant`+`colors`), **Multi Avatar**, **minidenticons**, **Nice Avatar** (`genConfig(seed)` or explicit config). Blob stays small (~200 B–1 KB JSON); no binary storage, re-render at any size. Trait picks store as `{hair: 'variant03', glasses: 'variant02', ...}` mapping 1:1 to `*Variant` options.
- **Rendered-asset model:** **Open Peeps** and **sprite kits** imply storing either selected part IDs (a *composite-config* blob — still small, but you ship part assets and write the stacker) or an exported PNG per avatar (upload-to-S3-style flow; Task Buddy's backend would render and persist files). **Notion-avatar maker** exports flat images → stored PNG per user.
- **Hybrid:** even with config-blob, caching a rendered PNG (e.g., 256px) per config is cheap and simplifies app-icon/leaderboard thumbnails; DiceBear's HTTP API can act as the render farm so the FastAPI backend only stores the config.

## Recommended shortlist for Task Buddy

1. **DiceBear (primary)** — `pixel-art` + one illustrated style (e.g., `lorelei` or `adventurer-neutral`):
   - Only candidate with official docs for *both* target platforms (Next.js server/client patterns; RN via `react-native-svg` or PNG API) ([RN](https://www.dicebear.com/integrations/javascript/react-native/), [Next.js](https://www.dicebear.com/integrations/javascript/next-js/)).
   - True slot model (`components`/`variants`) → gear overlay via derived-style component or second SVG layer ([style anatomy](https://www.dicebear.com/create-styles/from-scratch/)).
   - Storage = small config blob (`seed` + trait variants); HTTP API doubles as renderer and later mascot/icon source.
   - License hygiene: prefer **CC0 styles** (`pixel-art`, `open-peeps`, `notionists`, `lorelei`) to avoid attribution plumbing; `adventurer` requires visible CC BY 4.0 credit; `avataaars`/`bottts` are usable under artist terms.
   - Maintenance: actively developed (v10.7.0, pushed days ago), ~10k stars.
2. **Avataaars look — via DiceBear's `avataaars` style** (not the `avataaars` npm component): same slot-trait UX and friendly cartoon look, but inherit DiceBear's RN/Next paths and maintenance instead of the stale 2021 package. Gear maps to `accessories`/`clothes` slots.
3. **Boring Avatars or minidenticons (secondary, for defaults only)** — drop-in "no avatar chosen yet" placeholders; MIT, deterministic, zero per-user config beyond a seed. Not a customization engine.

**Rejected/flagged:** Multi Avatar (custom license restricts re-branding/competing avatar products; unmaintained), standalone `avataaars`/`react-native-avataaars`/`react-native-boring-avatars` packages (stale), Nice Avatar (viable MIT slot model but quiet since 2023-11 and no RN path), Multi Avatar / raw sprite kits (license audit + bespoke compositor cost).

## Gaps / unverifiable

- `react-native-avataaars`, `react-native-boring-avatars`, RN usage of `react-nice-avatar` and `minidenticons`: verified only by npm presence/staleness, not by running them — treat RN compatibility for non-DiceBear libs as *needs a spike*.
- Avataaars's own license text lives on `avataaars.com`, currently unreachable (expired TLS cert) — relied on DiceBear's licenses page summary ("free for personal and commercial use").
- "Similar or competing product/service" in the Multiavatar license is undefined; whether Task Buddy's avatar feature qualifies would need legal reading — another reason to prefer MIT/CC0 options.
- DiceBear `options.json`/`definition.json` endpoints are documented for API `10.x`; if self-hosting, confirm the hosted version tracks.
